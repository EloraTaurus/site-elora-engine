One Record, Two Views

The interactive HTML and downloadable JSON are derived from the same allow-listed public projection.

Certificate-Style Front Sheet

A concise record identity, generation context, final determination, Governability summary, authority timeline and checksum orient the reviewer before the detailed annex.

Interactive Evidence Annex

Expandable operations, stages, measurements, scoped gate outcomes, relationships and evidence gaps preserve depth without forcing every detail onto the front sheet.

Matching Portable Data

Embedded and downloadable JSON use the same bounded record. Report-local aliases replace private actor, process, thread and resource identifiers.

Stable References

Generation references and non-secret correlation values support review and comparison. Historical records do not gain identities or metadata that were never retained.

What the Record Can Show

Execution Outcome

Admission, observed changes, holds, release and terminal evidence can be summarised without replacing the underlying receipts.

Scoped Authority Evidence

Authority observations are tied to the operation and boundary where they were recorded. Tool permission, proposal approval and whole-execution authority remain different claims.

Measured Work

Available invocation, executor and CPU evidence can be presented with its scope. Shared execution infrastructure does not establish causal ownership.

Evidence Gaps

Unknown, conflicting, unavailable and historically unrecorded facts remain visible rather than being inferred from successful output or nearby telemetry.

Certificate Boundary

The record is an unsigned project evidence artifact. Its checksum supports internal consistency of the presented projection; it does not independently authenticate system origin, prevent third-party recreation, prove atomic enforcement, certify Governance, or establish that every relevant transition was captured.
